# MOR-3743: commander-owned exchange reservation

Design proposal only; no implementation or test execution. Paths are relative to `src/rigplane/` unless prefixed with `tests/`. Current-code statements cite symbols read; admission, permits, queue changes, and tests below are proposed.

## 1. Search and reuse

Round-2 caller search: `rg -n 'execute_civ_transaction|_send_civ_frame_now|_execute_civ_raw|execute_civ_raw' src/rigplane`; read those callers and the symbols cited below.
The nearest mechanism is `commands/commander.py: IcomCommander.send/_loop`: priority queue, cancellation propagation, background dedupe/cap, and per-item `is_current` already supply most of the execution machinery. Extend it; do not add a parallel seat lock or serializer.
`commands/commander.py: IcomCommander.transaction` performs snapshot → body → restore in `finally`, with no exclusion; `runtime/radio.py: CoreRadio.run_state_transaction` delegates to it or repeats that pattern without a commander. Preserve this helper's existing contract; reservation is a separate primitive.
`core/priority_exchange.py: PriorityExchangeGate.exchange` serializes one whole exchange and admits nobody during its body; it lacks holder-owned frames and safety passage. Reuse its cancellation lessons, not another gate around commander calls.
`runtime/_civ_rx.py: CivRuntime._execute_civ_raw` rechecks `is_current` after pacing and at transport dispatch. Retain this refusal mechanism, composing reservation currency with existing authority/session currency.
`runtime/_dual_rx_runtime.py: DualRxRuntimeMixin.write_relative_vfo_mode` reads omitted DATA/filter fields, checks a selection epoch, then queues SET and reads back; `_vfo_selection_change` records changes but excludes nothing. This permits concurrent preservation reads and lost updates, and a queued foreign select can still precede SET. Reservation must span preservation read through final readback, including fully specified writes.

## 2. Proposed API and ownership

```python
# Proposed foreign-frame admission option, separate from whole-request timeout:
await commander.send(payload, reservation_wait_timeout=0, timeout=request_budget)
async with commander.reserve(wait_timeout=0, hold_timeout=finite_budget) as token:
    # Same-task runtime calls attach token automatically at commander admission.
    current = await radio.read_relative_vfo(selected=False)
    # ... compose SET, await ACK, then read back under the same reservation ...
```

`reserve` is an async context manager on `IcomCommander`; it yields an opaque, commander-issued token tied to commander identity, lifecycle generation, and the owning `asyncio.Task`.
Capture context only at external admission (`send` or the explicit-transaction adapter), checking the actual caller task against the token owner. A copied `ContextVar` in a child task gives no privilege: treat that child's calls as foreign. No public adoption/transfer API in this slice.
The serializer receives explicit token metadata on each item; its executor task may use that metadata without impersonating the owner. Reject nested `reserve`, including same-task nesting, with `CommanderBusyError`; do not depth-count, replace ownership, or extend the outer deadline. Cross-commander tokens are invalid.
**Decision: reject-only first.** Both wait options default to zero and accept only zero in this series; reject positive, negative, NaN, and infinite values. Positive waits, acquisition waiters/tickets, and ingress wait-policy configuration belong to a separate follow-up. Require finite positive `hold_timeout`.
Grant only at a serializer boundary with no active exchange and no older parked-work fairness debt; otherwise `reserve(wait_timeout=0)` raises proposed `CommanderBusyError`, a subclass of `core/exceptions.py: CommandError`. Acquisition and dispatch share one state machine, with no yield between checking eligibility and installing ownership.
Foreign non-safety sends reject before enqueue/dispatch when ownership bars admission, including fire-and-forget calls; the awaited send reports busy before returning. Preserve baseline queueing when unreserved and for holder frames: a busy worker alone does not reject a send. Already accepted foreign items are parked, not retroactively rejected; cancellation/timeouts must prevent a later send.
Current `commands/commander.py: IcomCommander.send(timeout)` times a deduped future or its newly enqueued future. Keep that request budget without restarting it when parking/unparking; carry a monotonic deadline from send entry. No reservation-wait timer exists in this slice. Keep `runtime/_civ_rx.py: CivRuntime.execute_civ_transaction`'s radio-answer timeout starting after wire send, separately from an enclosing request deadline.
Busy means local contention, not a radio NAK (`core/exceptions.py: CommandRejectedError`). Hold/request/radio-answer expiry remains timeout; transport/session retirement remains `core/exceptions.py: ConnectionError`. Exact protocol mappings are part of seam 3.
`FORCE_RELEASE` and `ABORT` bypass reservation refusal, including during cleanup; existing exchange serialization, authority/lifecycle checks, and request deadlines still apply. Safety execution does not depend on holder-token currency.
Holder frames pass using their validated token, without another acquisition. Disable dedupe lookup and key registration while reserved or draining, including for safety frames; never join a pre-reservation foreign future. Preserve ordinary dedupe when unreserved; no token namespaces.
On normal exit, exception, or cancellation, release in a non-abandonable bounded finalizer; revoke queued holder ordinary frames before releasing. Do not grant the next owner until active execution has quiesced. Propagate the original exception unless lifecycle failure requires an explicit connection failure.
On stop/disconnect, revoke the generation, fail queued/parked items with `ConnectionError`, cancel/join active work, and clear ownership. Restart creates a fresh generation; old tokens never become valid again. This lifecycle teardown is distinct from holder expiry.
Only adopter in this series: `runtime/_dual_rx_runtime.py: DualRxRuntimeMixin.write_relative_vfo_mode`. Defer its `_run_with_receiver_vfo_fallback` and `write_relative_vfo_frequency`, and `web/radio_poller.py: RadioPoller._select_and_bind_vfo_slot` reservation adoption to a separate follow-up; they remain ordinary consumers of shared admission.

## 3. Exact priority policy

Current definitions: `commands/commander.py: Priority`; current actuator assignment: `runtime/radio.py: CoreRadio.actuate`.

| Tier | Value | Proposed foreign admission while reserved |
|---|---:|---|
| `FORCE_RELEASE` | -20 | Pass: forced receive/de-key, exact validated raw de-key, and authoritative PTT verification |
| `ABORT` | -10 | Pass: typed stop CW / tuner-off, managed or unmanaged after promotion |
| `IMMEDIATE` | 0 | Reject new foreign admission, including key-on |
| `NORMAL` | 10 | Reject new foreign admission |
| `BACKGROUND` | 20 | Reject new foreign admission, including fire-and-forget |

`runtime/radio.py: CoreRadio.set_ptt` currently sends both states at `IMMEDIATE`; `CoreRadio.stop_cw_text` uses `IMMEDIATE`, and `CoreRadio.set_tuner_status(0)` uses default `NORMAL`. In seam 3, promote unmanaged PTT-off to `FORCE_RELEASE` and unmanaged stop-CW/tuner-off to `ABORT`; key-on and tuner-on/tune remain ordinary admission.
At raw admission (`commands/commander.py: IcomCommander.send` and the proposed explicit-transaction adapter), **before foreign refusal**, validate the complete payload with existing `runtime/tx_interlock.py: is_exact_raw_dekey_frame`; a match promotes otherwise ordinary raw traffic, including rigctld `w`, to `FORCE_RELEASE`. Reuse its exact bare/0x29 validation for PTT-off, tuner-off, and voice-memory stop; no new classifier, no exemption for malformed/concatenated/extra-payload frames or key-on. Preserve typed `ABORT` assignments and existing ingress restrictions: `rigctld/handler.py: _RigctldCommandExecutor.execute` refuses managed raw TX-family frames. Raw callers cannot self-assert safety priority.
Ticket exemption is narrower: `rigctld/handler.py: RigctldHandler.execute` → `_is_raw_transmission_end_args` uses `runtime/tx_interlock.py: is_exact_raw_transmission_end_frame`, which excludes tuner-off; do not widen that exemption.
These are commander priorities, not `core/priority_exchange.py: ExchangeTier` (`FORCE_RELEASE=0`, `ABORT=10`, `URGENT=20`, `ORDINARY=30`). Do not conflate their numeric values.

## 4. Deadlock, starvation, and revocation

`commands/commander.py: IcomCommander.start/_loop` uses `asyncio.PriorityQueue`, with no selective dequeue. Seam 1 replaces it with commander-owned eligible and parked heaps plus a wake event; partition/reheapify on grant/release/revoke costs O(n), each eligible dispatch O(log n), excluding pruning abandoned entries. Preserve original priority/sequence/deadline, background accounting, and exact-once completion across both heaps. Never block the worker on a barred head.
Preserve FIFO within each eligible priority. On release, let older parked ordinary work cross a dispatch boundary before immediate reacquisition; zero-wait reserve refuses while that fairness debt exists. Safety stays first; perpetual safety traffic may exhaust ordinary request deadlines, never count as success. There are no acquisition waiters in this slice.
The non-renewable holder deadline runs even while its body is idle. On expiry, revoke its token, fail queued holder ordinary items, and cancel **only holder-owned ordinary active execution**. Never cancel an in-flight `FORCE_RELEASE`/`ABORT` or its result future because of holder expiry, regardless of its originating task; it finishes under its own existing deadline. Do not implement expiry by cancelling an owner awaiting safety: deliver the safety result, then report holder timeout on context exit/next ordinary admission; an expired token cannot fall back to unreserved sends. `runtime/radio.py: CoreRadio.actuate` waits for the FORCE_RECEIVE response, so killing that exchange would discard its de-key result.
Compose reservation currency with authority/session `is_current` at `runtime/_civ_rx.py: CivRuntime._execute_civ_raw/_send_civ_frame_now`, including pacing and final transport dispatch. Holder cancellation suppression cannot keep ordinary frames eligible. Await executor termination and response-tracker cleanup before another exchange; bytes already sent cannot be retracted.
Proposed holder-cleanup cap: **1.0 s**, not a measured production value. **Total de-key latency while held, admission → wire dispatch (or explicit failure): `T_dekey ≤ T_existing_inflight_exchange + T_existing_pacing + 1.0 s drain`.** Accept safety throughout cleanup and dispatch at first quiescence ahead of ordinary work, without awaiting holder exit or the timer. On drain overrun, fence/retire the generation and fail blocked work, including safety, with `ConnectionError`; never overlap exchanges or cancel an in-flight safety exchange with this timer. Validate the **full sum** against MOR-1881's no-added-in-band-unkey-delay ruling (`rigctld/handler.py: RigctldHandler._defer_write_gate`); this proposal is not proof of budget compliance.
`commands/commander.py: IcomCommander._loop` awaits one `execute_task`; safety admission is not preemption of an executing exchange. Preserve its exchange deadline and single ACK/NAK ownership. `IcomCommander.send/_loop` already propagates cancellation and skips abandoned futures; extend that accounting to parked items, rechecking original authority/session predicates and deadlines at dispatch.
No unrelated I/O, callbacks waiting on foreign commands, or unbounded work inside a reservation. Holder cleanup cannot acquire a foreign resource whose owner is waiting for commander admission. Any later VFO restore runs while ownership is valid; failed restore must report uncertainty, not a fabricated restored state.

Out-of-commander paths must be addressed before claiming exclusion for all in-process CI-V writers:

- Close `runtime/radio.py: CoreRadio.send_civ_transaction` and `runtime/_civ_rx.py: CivRuntime.write_managed_ptt/request_authoritative_ptt_read/execute_civ_raw`, plus `CivRuntime._send_civ_raw`'s fallback. Apply §3 exact raw validation before refusal; a managed port token or unvalidated bytes confer no safety priority. A poller pause cannot substitute for admission.
- For both identity readers and both hold-only POWER ON paths, use a simple `no_reservation` flag, **not lifecycle permits**: set it before direct hold I/O, atomically excluding ownership/active exchanges; refuse reserve while set. Closing these direct paths, especially managed physical key-on, is a release prerequisite: wrapping the first adopter alone cannot close F4. Keep direct safety writes admitted under the same commander state machine, avoiding recursive enqueue from its own executor. External physical radios/front panels and other processes are outside this in-process exclusion guarantee; keep epoch/readback and authority checks for invalidation, not as substitutes for reservation.

## 8. Remaining coordinator question

1. Hold-budget value: recommend `min(remaining_caller_budget, sum(exchange_answer_bound + pacing_bound + drain_bound for each of at most five exchanges) + 1.0 s cleanup)`; all component bounds must be finite, using the sum when no caller deadline exists. Record the concrete value before implementation acceptance.

Ingress policy is decided: reject-only, retry by the client. Positive waiting and later reservation adopters require a separate follow-up and estimate.
